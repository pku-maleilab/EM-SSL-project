Importing Fine-tuned Models

You can train your own OmniEM heads with the omniem-train repository and load them into Napari-OmniEM through Add Solution. This page walks through two worked examples from that repository's examples/ folder:

  • EMPIAR-11831: a 4× super-resolution head (Image-to-Image).
  • ME2-Beta: a mitochondria segmentation head (Image-to-Label), in 2D and 3D variants.

For the general Add Solution reference, see Importing Your Own Models.

What training produces

After you run a training example (omniem-train train … infer), the run's output_dir holds everything you need to import:

outputs/<run>/
  model.yaml              # the model-config file you select in Add Solution
  weights/
    backbone.pt           # the shared EM-DINO ViT-L backbone
    head_best.pt          # the trained head (best validation score)
    head_e<NNN>.pt        # per-epoch heads

Both examples freeze the backbone (train.train_encoder: false), so the backbone is the same EM-DINO ViT-L that Napari-OmniEM already ships as EMDINOv1-ViTL (tag 4246a479). That means you import only the head, using the Head-only strategy, and pair it with the existing backbone.

If the head-only importer doesn't recognize the backbone

Use the Full-scale strategy on the run's combined checkpoint instead, it splits the file into a backbone + head and registers the backbone for you. See Importing Your Own Models.

Example 1: 4× super-resolution (Image-to-Image)

Source: omniem-train/examples/EMPIAR-11831 (SBF-SEM tobacco tissue). The head restores detail lost to 4× downsampling. Its model.yaml:

arch: omniemv1
encoder: emdinov1
img_z: 1
out_channels: 1          # one grayscale map
kernel3d_z: null
task_type: image2image
resize4emdino: true

Import it:

  1. Open Preferences (⚙️) → Tasks and Models → Solutions and select (or create) an Image-to-Image task.
  2. Click Add Solution, then Select model config and pick the run's model.yaml.
  3. Choose the Head-only strategy, select weights/head_best.pt, and pair it with EMDINOv1-ViTL.
  4. Confirm. The head is copied into the managed weights folder and the solution appears in the task.

Use it: run it like any Image-to-Image solution (see In-memory Inference). This head is trained for 4×, so set the Scale (×) control to 4.0 for its intended factor.

Example 2: mitochondria segmentation (Image-to-Label)

Source: omniem-train/examples/ME2-Beta (FIB-SEM, part of the MitoEM 2.0 benchmark). The head maps each EM image to a two-class mask, background (0) and mitochondria (1). Two configs share the data:

Variant img_z kernel3d_z Sample shape
2D (run_mito_2d) 1 null 224 × 224 × 1
3D (run_mito_3d) 16 3 224 × 224 × 16

The 2D model.yaml:

arch: omniemv1
encoder: emdinov1
img_z: 1
out_channels: 2          # background + mitochondria
kernel3d_z: null
task_type: image2label
resize4emdino: false

Import it:

  1. Select (or create) an Image-to-Label task whose labels are Background and Mitochondria (two labels, matching out_channels: 2).
  2. Click Add Solution, select the run's model.yaml, choose Head-only, pick weights/head_best.pt, and pair it with EMDINOv1-ViTL.
  3. Confirm. Repeat with the 3D run's model.yaml + head_best.pt to add the 3D variant as a second solution (it needs z ≥ 16).

Use it: run it like any Image-to-Label solution. The output is a mask with the Background / Mitochondria labels.

After importing

Imported solutions behave exactly like the built-ins: they appear in the Task / Solution menus for in-memory and local inference, and you can export or share them. To manage the shared backbone they run on, see Backbones.
