Task & Solution Management

Napari-OmniEM lets you manage tasks and solutions (models + configurations) from the GUI. Open ⚙️ Preferences → Tasks and Models → Solutions.

Screenshots

Some screenshots on this page show the v0.2 interface and are pending update.

Concepts

  • A Task defines the problem type, Image-to-Image (e.g. denoising, super-resolution) or Image-to-Label (e.g. mitochondria segmentation).
  • A Solution is a concrete model + configuration that solves a task. A task may hold several solutions; each solution belongs to exactly one task.

Adding your own solutions and managing shared backbones has its own page:

  • Importing Your Own Models: the Add Solution flow and the shared backbones behind every model.

Managing tasks

New Task

Click New Task and provide:

  • Task Type: Image-to-Image or Image-to-Label.
  • Full Name: the name shown in the GUI selection menus (must be unique).
  • Short Name: a concise identifier used to store the task's config file (must be unique).

For an Image-to-Label task, also define each output label and its meaning; each label is one output class of the model.

Enable / Disable Task

Select a task, then use Enable Task / Disable Task (only the applicable one is active). A disabled task does not appear in the in-memory or local inference menus; its solutions stay stored and return when you re-enable it.

Delete Task

Delete Task removes a task and its config permanently. If the task's solutions have head files inside the managed weights folder, you're asked whether to delete those files too or keep them. The shared backbone is never deleted here.

Dump Task / Import Task (sharing)

Move a whole task between installs:

  • Dump Task writes the task description only: a .yaml listing its solutions. It does not copy weights.
  • Import Task reads such a .yaml back and registers the task under a unique short name you provide, pointing it at a folder that holds the weight files.

Because Dump writes only the description, sharing a task means sending both the dumped YAML and the weight files:

  1. Dump Task → get mytask.yaml.
  2. Export Weights for each solution (see Importing Your Own Models) into a folder.
  3. Send the YAML + the weights folder.
  4. The recipient uses Import Task, selects the YAML, points at the weights folder, and gives a unique short name.

Head files must match the YAML

Every solution's head file must be present in the selected weights folder and its filename must match the one recorded in the dumped YAML. If you renamed a Split export, update the YAML (or re-export) so the names line up, otherwise the import can't find the weights.

Managing solutions

Add Solution

Click Add Solution to import a fine-tuned OmniEM model into the selected task. The full flow, model-config file, full-scale vs head-only strategy, and what the validation messages mean, is documented in Importing Your Own Models.

Solution metadata cannot be changed after a solution is added; to change it, remove the solution and add it again.

Remove Solution

Select a solution and click Remove Solution. If the solution's head file lives in the managed weights folder, you're offered a choice: delete the file too, keep it, or cancel. Removing a solution deletes it from the task config; a shared backbone is never removed by this action.

Export Weights

Export Weights writes a solution's weights out as a Combined single .pt or a Split pair (backbone + head); see Importing Your Own Models.

Best practices

  • Use descriptive task and solution names.
  • Dump a task (and export its weights) before major changes.
  • Keep your weights in the managed weights storage folder so the plugin can find and move them for you.
